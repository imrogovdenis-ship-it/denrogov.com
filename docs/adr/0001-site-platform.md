# ADR-0001: платформа denrogov.com

- Статус: принято
- Дата: 2026-08-31
- Связанные задачи: ROG-21, ROG-22, ROG-23, ROG-32

## Контекст

Production уже работает как статический экспорт Tilda под nginx и содержит
маршруты, связанные с оплатой AI Class. Немедленная смена runtime повышает риск
регрессии без пользы для текущих security и observability исправлений. Следующая
версия должна поддерживать статические страницы, растущий блог и безопасную
автопубликацию без обязательного Node.js runtime в production.

## Решение

1. Текущий production-контур остаётся `static HTML + nginx + Docker + Coolify`
   до готовности дизайна ROG-20 и новой главной ROG-22.
2. Целевой стек контролируемого rebuild — Astro в режиме static output.
3. Миграция выполняется по маршрутам, с сохранением существующих URL, canonical,
   sitemap, форм, платёжных переходов и nginx-редиректов.
4. API публикации и health из ROG-32 разворачивается отдельно от публичной
   статики. Он публикует валидированный контент через GitHub, а не получает
   произвольный доступ к webroot.

## Почему Astro

- статический результат без обязательного application server;
- content collections и schema validation подходят для блога;
- минимальный клиентский JavaScript по умолчанию;
- проще сохранить существующий nginx/Coolify deployment и быстрый rollback;
- Next.js не даёт нужного преимущества, пока SSR и server actions не входят в
  подтверждённые требования.

## Последствия

- ROG-22 начинается после передачи HTML-прототипа и design tokens из ROG-20;
- текущие исправления продолжают поставляться независимо от rebuild;
- DNS нельзя переключать до проверки payment smoke-test и готового rollback;
- добавление серверного API требует отдельной модели авторизации, rate limit и
  журнала публикаций.
