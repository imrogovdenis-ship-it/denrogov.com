# Игра-виджет для бота @portalvr — дизайн

Дата: 2026-11-11. Статус: ожидает проверки владельцем.

## Цель

Аркадная игра «тапай, чтобы лететь» прямо в сообщении бота @portalvr как HTML-виджет
Telegram Bot API 10.4. Игроки соревнуются за место в общем топ-10; приглашение друзей
и подписка на канал @portal_vr_news повышают итоговый результат и приводят новых людей.

Успех: человек нажимает `/start`, играет не выходя из чата, видит себя в рейтинге,
зовёт друзей и подписывается на канал ради коэффициента.

## Ограничения платформы (из официальной документации)

- В продакшене виджеты работают только в личном чате с ботом. Группы, инлайн-режим и
  пересылки — только на тестовом сервере; в каналы виджеты не отправляются.
- Виджет — один HTML-документ: до 32 768 байт и до **4096 байт после zlib уровня 9**.
- Код исполняется в песочнице QuickJS без сети. Единственный выход наружу —
  `TelegramWidget.request(data)` с данными 1–64 байта; бот получает `widget_query` и
  обязан ответить `answerWidgetQuery` за 15 секунд (ответ до 1024 байт).
- Один запрос на один тап, один запрос в полёте, 5 запросов за 5 секунд на пользователя.
  В личном чате разрешены фоновые запросы: один при появлении виджета, далее не чаще
  раза в 5 секунд.
- Клавиатуры и полей ввода нет. Вертикальные жесты принадлежат чату, тапы — виджету.
- В canvas нет теней, `globalCompositeOperation` и фильтров; шрифты только системные.
- Общее состояние (`public_data`) и состояние чата (`chat_data`) — текст до 1024 байт,
  пишет только бот. Общий виджет редактируется не чаще раза в секунду.
- Код виджета после отправки не меняется: новая версия игры — это новый виджет.

## Игра (виджет)

- Canvas фиксированного размера около 340×440 логических пикселей, `touch-action: none`.
- Тап — взмах. Птичка в очках летит через «ворота» из неоновых кубиков двух цветов
  со стрелками; графика оригинальная, без чужих персонажей и ассетов.
- +1 очко за каждые ворота; скорость плавно растёт до потолка.
- Неон рисуется градиентами и обводкой (тени в canvas недоступны).
- Экраны:
  1. **Старт** — название, коэффициент игрока, кнопка-подсказка «Тапни, чтобы лететь».
  2. **Игра** — счёт сверху.
  3. **Финал** — очки, разложение «37 × 1.2 = 44», личный рекорд, топ-10, строка
     «Твоё место: 35», кнопки «Ещё раз», «Позвать друга», «Подписаться».
- Порога входа в рейтинг нет: учитывается любой результат. В таблице показаны первые
  десять мест, а каждому игроку отдельно сообщается его собственное место, даже если
  оно далеко за пределами десятки. Игрок из топ-10 подсвечен в таблице.
- Результат отправляется боту автоматически в конце забега, без отдельной кнопки.
  Если Telegram не пропустил фоновый запрос (лимит — один в 5 секунд), на финале
  появляется кнопка «Узнать место», и результат уходит по её тапу.
- Имя в рейтинге — имя из профиля Telegram. Оно видно другим, только если игрок вошёл
  в топ-10; об этом сказано в подписи к сообщению с игрой.
- Личный рекорд и коэффициент кэшируются в `localStorage` и обновляются ответами бота.
- Учитывается `prefers-reduced-motion` и пауза, когда виджет ушёл с экрана.
- Вне Telegram (`TelegramWidget` не определён) игра запускается без рейтинга — это
  режим для разработки и тестов.

## Протокол виджет ↔ бот

Запросы (текст до 64 байт):

| Запрос | Когда | Что делает бот | Ответ (JSON) |
|---|---|---|---|
| `i` | фоном при появлении виджета | проверяет подписку, считает друзей | `{k, b, p, f, s}` — коэффициент, рекорд, место (0, если результата ещё нет), число друзей, подписка |
| `s` | тап, начинающий забег | фиксирует время старта; первый забег приглашённого засчитывает его пригласившему | `{}` |
| `e:<очки>` | фоном в конце забега, либо тап «Узнать место» | проверяет забег, считает итог, обновляет рекорд и топ | `{v, k, b, p, t, r}` — итог, коэффициент, рекорд, место, топ-10, ревизия |

На любую ошибку бот отвечает коротким `{"err":"…"}`; виджет показывает понятный текст
для каждого кода ошибки (`TIMEOUT`, `RATE_LIMITED`, `FAILED`, отказ бота).

## Рейтинг

- Один общий (shared) виджет на версию игры. Топ-10 лежит в его `public_data`:
  `{"r": ревизия, "t": [["Имя", итог], …]}`; имена обрезаются до 16 символов, чтобы
  десять строк гарантированно уместились в 1024 байта.
- Виджет вызывает `watchPublicData()` и перерисовывает таблицу по `publicDataChanged`,
  игнорируя ревизии старше уже показанной.
- У игрока одна строка — лучший итоговый результат. При равенстве выше тот, кто
  набрал раньше.
- Место игрока — число игроков с лучшим итогом плюс один; считается по всем игрокам,
  а не только по десятке, и приходит в ответах на `i` и `e`.
- `public_data` обновляется только когда топ-10 изменился. Если упёрлись в лимит
  «раз в секунду», ставится флаг «нужно обновить», и запись происходит при следующем
  запросе любого игрока. Отправивший результат всё равно видит свежий топ из ответа.

## Коэффициенты

`итог = округление(очки × k)`, где `k = 1 + 0.1 × подписка + 0.1 × min(друзья, 15)`.
Максимум — ×2.6.

- **Подписка на @portal_vr_news: +0.1.** Проверяется через `getChatMember` при каждом
  `i` и `e`. Бот должен быть администратором канала. Отписка убирает бонус для новых
  результатов; уже записанные не пересчитываются. Если проверка не удалась, бонус не
  начисляется, а результат записывается.
- **Друзья: +0.1 за каждого, максимум 15.** Кнопка открывает окно «Поделиться» со
  ссылкой `https://t.me/portalvr?start=r<id>`. Друг засчитывается, когда новый для бота
  пользователь пришёл по ссылке и начал хотя бы один забег. Себя пригласить нельзя;
  у пользователя может быть только один пригласивший, и он не меняется.
- Коэффициент считает только бот. Виджет его показывает, но не присылает.

## Бот (Supabase Edge Function)

- Одна функция-вебхук в существующем проекте Supabase. Проверка JWT выключена;
  вместо неё — секретный заголовок `X-Telegram-Bot-Api-Secret-Token`.
- Секрет проекта один — токен бота; в репозиторий он не попадает. Секрет вебхука
  функция выводит из токена (HMAC-SHA256) и сама сообщает его Telegram.
- `GET …/portal-game/setup` устанавливает вебхук и показывает, является ли бот
  администратором канала. `GET …/portal-game` показывает версию сборки и целость
  встроенного кода игры.
- Обновления: `message` (команда `/start` с необязательным параметром `r<id>`) и
  `widget_query`. Всё остальное игнорируется с ответом 200.
- `/start`: регистрирует игрока, запоминает пригласившего, отправляет игру через
  `sendSharedWidget` с подписью. Если общего виджета для текущей версии HTML ещё нет,
  функция создаёт его первой отправкой `sendWidget` с `is_shared` и `allow_queries`
  и сохраняет `widget_id`.
- HTML виджета встраивается в функцию на этапе сборки.

## Данные

Таблицы в схеме `public` с префиксом `flap_`, RLS включён без политик: публичному API
они недоступны, функция работает под сервисной ролью. Существующие таблицы проекта не
затрагиваются.

- `flap_players` — id пользователя, имя, username, лучший итог и когда он набран,
  пригласивший, признак «сыграл хотя бы раз», даты.
- `flap_runs` — текущий забег игрока: время старта (одна строка на игрока).
- `flap_config` — `widget_id` по хэшу HTML, ревизия и снимок топ-10, флаг «нужно
  обновить», время последней правки общего виджета.

Запись результата выполняется одной SQL-функцией, чтобы параллельные запросы не
портили рекорд и топ.

## Защита от накрутки

Код виджета публичен, а очки присылает он сам, поэтому полностью исключить подделку
нельзя. Бот отсекает очевидное:

- `e` принимается только при наличии забега, начатого запросом `s`, и забег расходуется.
- Очки не могут превышать число ворот, физически проходимых за время между `s` и `e`
  (с небольшим допуском), и общий потолок.
- Забег старше 30 минут не принимается.
- Друг засчитывается только как новый пользователь, начавший забег.

Если накрутка всё же появится, владелец может удалить строку игрока в таблице; топ
пересоберётся при следующем результате.

## Структура кода

Папка `telegram-game/` в этом репозитории:

- `widget/` — исходник игры (HTML, CSS, JS) и чистая игровая логика отдельным модулем.
- `build/` — сборка: минификация, проверка лимитов 32 768 и 4096 байт, генерация
  модуля с HTML для функции. Сборка падает при превышении лимита.
- `supabase/functions/portal-game/` — вебхук: разбор обновления, обработчики
  `/start`, `i`, `s`, `e`, клиент Bot API, доступ к данным.
- `supabase/migrations/` — таблицы и SQL-функция записи результата.
- `tests/` — тесты.
- `README.md` — инструкция владельцу: секреты, вебхук, права бота в канале.

Сайт и его деплой не меняются.

## Тестирование

- Игровая логика: физика, столкновения, начисление очков, рост скорости.
- Бюджет размера: собранный виджет ≤ 4096 байт после zlib-9.
- Бот: обработчики на поддельных обновлениях с подменённым Bot API и хранилищем —
  старт, реферал, отказ на самоприглашение, проверка правдоподобия очков, расчёт
  коэффициента, сборка топ-10 и его размер ≤ 1024 байт, отказ без секретного заголовка.
- Виджет в браузере с имитацией `TelegramWidget`: забег, финал, запросы, перерисовка
  таблицы.
- В настоящем Telegram проверка возможна только после подключения токена владельцем;
  до этого результат считается проверенным в браузере и на тестах, но не в клиенте.

## Что нужно от владельца

1. Токен @portalvr — в секреты проекта Supabase (`BOT_TOKEN`).
2. Сделать @portalvr администратором канала @portal_vr_news.
3. Один раз открыть в браузере ссылку установки вебхука из `telegram-game/README.md`.
